# 良い動画の基準と、作るときの手順

新しい型を作るとき・既存の型を直すときに、最初に読むものです。
基準は、チャンネルの持ち主が実際の動画に付けた指摘から作りました（元の指摘は [`FEEDBACK.md`](FEEDBACK.md)）。
指摘が増えたら、ここの基準も直します。

## 1. 設計の決まり

| # | 決まり | 理由（実際にあった指摘） |
|---|---|---|
| 1 | **増える・減る理由が、画面の中の出来事として見える。** 挟まれて潰れる、壁に当たる、光線に触れる、など | 「潰れてない時も増えてる」「分裂のタイミングが意味不明」 |
| 2 | **物が突然現れない・消えない。** 現れるなら割れたその場所から。消えるなら、当たった物としるしを見せる | 「真ん中から急に玉が出現している」「玉が途中で消えている」 |
| 3 | **勝ち負けのある型は、最初の条件を変える。** 全員同じ条件だと、くじ引きと変わらない | 「同条件で始まってるからあみだくじと何も変わらない」 |
| 4 | **条件を変えたら、勝率を試算でそろえる。** どれかが勝つのが当たり前に見えてはいけない | 「当然赤が勝つのは当たり前すぎる」 |
| 5 | **数字は丸める**（有効数字 3 桁まで。1,537 ではなく 1,500 や 1,540。0 の多い数字ほど良い） | 「数値設定がこまかい、もっと 0 を使って見やすく」 |
| 6 | **結果が先に分かる表示をしない**（ゴールまでの残りマス数、など）。残りの回数や枚数は出してよい | 「ゴールまで何マス表示するかは結果が分かってしまう」 |
| 7 | **軌跡や線を残さない。** 背景は最後まできれいに | 「軌跡が残り続けるのが不必要、最後に背景が汚く見える」「変な線がある」 |
| 8 | **仕掛けは規則正しく動かす。置いた部品は全部働かせる** | 「ハンマーの動きが不規則すぎる」「右上と左下のアームが機能していない」 |
| 9 | **音は心地よく。** 音階に沿わせ、同じ音の繰り返しにしない。画面で何も当たっていないのに鳴らさない。無音を続けない | 「音が単調で雑」「当たって無いのに音が鳴る」「不協和音」 |
| 10 | **遅くしない。最後は弾けて終わる** | 「動きが遅くて爽快感が無い」「連鎖的な爆発が欲しい」「爆発力に欠ける」 |
| 11 | **長さは 20〜45 秒。** 決着が早すぎても、間延びしてもいけない | 「決着が早すぎ」 |
| 12 | **文字は英語で、何の表示か分かるように。** 画面の端から離す | 「これは何語？」 |
| 13 | **他人の映像・音楽・キャラクター・ロゴ・実在の人物を使わない。** 曲は著作権の切れたクラシックだけ | 収益化と削除を避けるため |

勝ち負けのない「眺める型」（埋め尽くし、釘の板、連鎖など）は 3・4 が当てはまりません。
そのかわり、10（最後に弾ける）と 9（音）が出来を決めます。

## 2. 作るときの手順

| 手順 | やること | 道具 |
|---|---|---|
| ① 絵なしで回す | 落ちないか、長さ、勝ち方のかたより。条件の違うレースは、ここで数字を直す | `python video/tools/balance.py 型 --seeds 1-64` |
| ② 試し書き出し | 低画質で 1 本。見た目と文字の位置 | `python video/make.py 型 --seed 1 --preview` |
| ③ 本番 | 1080×1920・60 コマ/秒 | `python video/make.py 型 --seed 1` |
| ④ 機械で点検 | 下の §3 | `python video/tools/review.py 動画.mp4` |
| ⑤ 目で点検 | 下の §4。④が作る一覧画像を開いて確かめる | |
| ⑥ 見てもらう | 動画を送り、指摘をもらう | |
| ⑦ 記録する | もらった指摘を `FEEDBACK.md` に足す。基準が変わるなら、このファイルも直す | |
| ⑧ 順番に入れる | **「良い」と言われた型だけ**、`post_queue.txt` か `next_post.py` の `ROTATION` に入れる | |

気をつけること:

- **試し書き出し（30 コマ/秒）と本番（60 コマ/秒）は、結果が変わる型がある。** 勝者や長さは本番で確かめる。
- **既存の型の部品を直したら、`python video/tools/smoke.py --golden` を回す。** 順番待ちの動画の中身が
  知らないうちに変わっていないかを確かめる（変えるつもりで変えたときだけ `--update`）。
- 新しい型は `registry.py` の 2 か所（`SIMS` と `COPY`）と `README.md` の一覧に足す。

## 3. 機械で調べる項目（`tools/review.py`）

| 項目 | 基準 | 外れたときに疑うこと |
|---|---|---|
| 長さ | 20〜45 秒 | 決着がつかない／早すぎる |
| 大きさ | 1080×1920 | `--preview` のまま送ろうとしている |
| ファイル | 70MB 以下 | 細かい粒が多すぎる（towers 系は 60MB 前後になる） |
| 平均音量 | −27〜−14 dB | 音が少なすぎる／重なりすぎ |
| 最初の音 | 1.2 秒以内 | 出だしで何も起きていない |
| 途中の無音 | 2 秒未満 | 個数が少ないあいだ、当たった音が鳴っていない |
| 動きが止まる | 4 秒未満 | 全部が止まっている |
| 画面全体が変わらない | 8 秒未満 | 動いてはいるが、勢力や量が変わっていない（不採用にした `colorwar2` がこれ） |
| 端 | 上 4%・下 3%・左右 2% に絵や文字がない | 題名が端に寄りすぎ |

## 4. 目で見る項目（機械では分からない）

一覧画像（8 コマ）と、必要なら `--close 秒` の細かいコマ送りで確かめます。

- [ ] 増える・減る瞬間を細かいコマ送りで見て、理由が絵で分かるか（§1 の 1・2）
- [ ] 途中のコマだけ見て、勝者が読めてしまわないか（§1 の 4・6）
- [ ] 最後のコマの背景に、跡や線が残っていないか（§1 の 7）
- [ ] 置いた部品が全部働いているか。働いていない部品は消すか、形を直す（§1 の 8）
- [ ] 数字が丸いか。途中の表示も含めて（§1 の 5）
- [ ] 途中で「残り ○ 個」が長く動かない時間がないか
- [ ] 最後が弾けて終わるか。弾けたあと、何かが取り残されていないか（§1 の 10）
- [ ] 文字が小さすぎないか（一覧画像ではなく、本番の大きさの 1 コマを切り出して確かめる）

## 5. これまでに分かったこと（数字）

- 再生数は [`docs/stats/README.md`](../docs/stats/README.md) にある（1 日 1 回更新）。
- 2026-11-23 時点で一番伸びたのは `gear`（約 2.2 万回、平均視聴率 85%）。ほかは 850〜1,700 回。
  「挟まれて潰されると増える」型が今のところ一番強い。
- 見ている人の半分はアメリカ。日本は 1 割弱。題名と文字は英語を先にする。
- TikTok と X は公開されているが、ほとんど再生されていない。YouTube を主にする。
