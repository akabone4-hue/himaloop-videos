# 3D 動画の作り方メモ（Blender）

3D の型（`marble`・`faces`）を作る中で分かったことをまとめたものです。新しい 3D の型を足すとき、
ギミックを増やすとき、うまく動かないときに読みます。数字はすべてこのリポジトリで実際に測った値です。

## 1. 全体の流れ

```
make.py marble --seed 21
  └ sims_3d.run_marble            文字と音を重ねる係（pygame）
      └ blender_marble.py          別プロセス。絵を描く係（Blender）
          ① コースを組み立てる       build()
          ② 物理を最後まで回す       simulate()  → 各コマの位置を記録
          ③ 引っかかったら作り直す    シードを +1000 して ① へ
          ④ カメラの高さを決める     camera_track()
          ⑤ 1 コマずつ描く          f_0001.png ...
          ⑥ 記録を書き出す          race.json
      ← コマ画像と race.json を読み、題名・順位・勝者・音を重ねて mp4 にする
```

絵（Blender）と、文字・音（pygame）を分けているのが要点です。
文字や音を直すだけなら、絵を描き直す必要がありません（下の「コマ画像を残す」を参照）。

## 2. 準備

| 項目 | 内容 |
|---|---|
| 入れるもの | `pip install -r video/requirements-3d.txt`（`bpy==5.3.0`、約 430MB） |
| Python | 3.13（bpy 5.3 の配布物が 3.13 用） |
| 描画方式 | Cycles を CPU で使う。EEVEE は使えない（画面のない Linux では `libEGL` がなく起動に失敗した） |
| GitHub Actions | `post-video.yml` と `make-videos.yml` は、3D の型のときだけ bpy を入れるようにしてある |

## 3. 速さの実測（4 コアのマシン）

| 設定 | 1 コマ | 30 秒（900 コマ）の目安 |
|---|---|---|
| 360×640・3 サンプル（`--preview`） | 約 0.4〜0.5 秒 | 約 6 分 |
| 720×1280・4 サンプル | 約 2.3〜2.9 秒 | 約 40 分 |
| 810×1440・6 サンプル（本番の設定） | 約 3.8〜4.4 秒 | 約 60 分 |
| 1080×1920・4 サンプル | 約 3.5〜4.1 秒 | 約 55 分 |
| 720×1280・8 サンプル＋ノイズ除去 | 約 8〜13 秒 | 2〜3 時間 |
| 1080×1920・6 サンプル＋ノイズ除去 | 約 15〜16 秒 | 約 4 時間 |

- 本番の実績: `marble` 660 コマ（22 秒）で 58 分。ほかの書き出しと同時に動かしたので、単独ならもう少し速い。
- ノイズ除去は 1 コマあたりの時間を 3〜4 倍にする。使わず、サンプル数を少し増やすほうが得。
- GitHub Actions での実績: `chime2`（810×1440・8 サンプル、約 20〜30 秒ぶん）の書き出しが 46 分、準備を含めた全体で 47 分（2026-11-23）。手元の 4 コアとほぼ同じ速さだった。
- 同時にほかの書き出しを走らせると、その分だけ遅くなる（4 コアを分け合う）。

## 4. 画質の設定で効いたもの

`setup_render()` に入っている設定と、その理由です。

| 設定 | 理由 |
|---|---|
| ノイズ除去なし | 上のとおり、時間がかかりすぎる |
| 光の跳ね返りを少なく（全体 2、拡散 1） | 見た目はほぼ変わらず速くなる |
| コースティクス（光の集まり）を切る | ノイズの元。この絵では要らない |
| 色の変換を `Standard` にする | 初期設定のままだと色がくすむ。ショート動画向けに鮮やかにする |
| 太陽光の角度を小さく（1〜2 度） | 影がくっきりして、少ないサンプルでもざらつきにくい |
| 810×1440 で描いて 1080×1920 へ拡大 | 1080 で描くより速く、スマホで見る分には差が小さい |
| `use_persistent_data` | コマごとの準備を使い回して速くなる（布のように形が変わる場面では切る） |

## 5. 物理（ビー玉とコース）で分かったこと

**大きさと精度**
- ビー玉の半径は 0.24。0.2 より小さい物は物理エンジンが苦手。
- 1 コマあたりの細かい刻みは 24、解く回数も 24。これで薄い板をすり抜けない。
- 形は単純なものを使う。坂は箱（BOX）、ビー玉は球（SPHERE）、釘は凸包（CONVEX_HULL）。

**跳ね返りと摩擦**
- 2 つの物の値は掛け算で効く（跳ね返り 0.5 と 0.6 なら 0.3）。片方だけ上げても思ったほど弾まない。
- 釘は 0.85 と高め、階段は 0.35 と低めにして、ギミックごとに感触を変えている。

**動くギミック（羽根・ハンマー・水車・ゲート）**
- 「コマ番号から角度を出す式」で動かす（`drive()`）。キーフレームを打つ方法は Blender 5 で作法が変わっていて、式のほうが確実。
- 物理側では「アニメで動く物」（kinematic）にする。ビー玉を押すが、ビー玉からは押されない。

**奥行き**
- ビー玉は奥の板と、手前の「見えないガラス」のあいだ（奥行き 1.05）を転がる。
- 見えないガラスは「描かないが、当たり判定はある」箱（`hide_render`）。これがないと手前に落ちる。

**詰まりの原因と直し方**（実際に起きたもの）

| 起きたこと | 原因 | 直し方 |
|---|---|---|
| 釘と壁のあいだに挟まって止まる | すき間（0.39）がビー玉の直径（0.4）とほぼ同じだった | 壁ぎわは釘をやめ、小さな斜面にした |
| じょうごの出口で詰まる | 出口が直径の 2 倍前後で、2 個が支え合ってアーチになった | 出口を直径の 2.6〜2.9 倍に広げた |
| じょうごの下の山形の頂点に乗って止まる | 左右対称の尖った形の上で釣り合った | 山形をやめ、丸い釘 1 本にした |
| 羽根と壁のあいだで押しつぶされる | 羽根の先と壁のすき間が直径より狭かった | 羽根を短くして、すき間を直径より広くした |

- 目安: **すき間は「直径より十分広い」か「直径よりはっきり狭い」のどちらかにする。** 同じくらいが一番危ない。
- 平らな面と左右対称の尖った形は、止まる場所になる。面には必ず傾きをつける。

**詰まりの検出**
- `simulate()` は、ゴール前のビー玉が 2.5 秒動かなかったら「詰まった」とみなす。
- そのコースは捨て、シードを +1000 して作り直す（最大 12 回）。
- 新しいギミックを足したら、まず `--quality none` で 20〜30 個のシードを回して、詰まりの回数を数える。
  じょうごを直す前は 12 個中 9 個で詰まり、直したあとは 24 個すべて完走した。

## 6. 「物理」と「描く」を分ける

これを知らずに 2 回つまずきました。

**ビー玉（剛体）**
- 物理を回しながら位置を記録し、**描く前に物理の世界を外して**（`rigidbody.world_remove()`）、記録した位置にビー玉を置く。
- こうしないと、コマを飛ばして描いたとき（`--step 10`）に物理が進まず、ビー玉がスタートに残ったままの絵になる。
- 位置の記録は音づくり（どこで当たったか）と順位表示にもそのまま使える。

**布**
- 布は位置の記録では済まないので、**描く前に全部計算しておく**（`ptcache.bake_all(bake=True)`）。
- これを忘れると、描くコマでしか計算が進まず、9 コマおきに描けば 9 分の 1 の速さのスローモーションになる。

**覚えておくこと**: `scene.frame_set()` で進めた計算と、`render()` が中で行う計算は別物。
描く側に頼らず、位置を自分で記録するか、先に全部計算しておく。

## 7. 文字と音の重ね方

**当たった瞬間の拾い方**（`_hits()`）
- 記録した位置から速度を出し、前のコマからの変化（重力による分は除く）が大きいところを「当たった」とみなす。
- 釘の区間では木琴の音、それ以外では木の「コツッ」という音を鳴らす。強く当たるほど大きくする。

**色**
- 画面で見せたい色（0〜255）を `NAMES` に 1 か所だけ書き、Blender の材質へ渡すときに `linear()` で直す。
- 順位の丸も同じ `NAMES` の色を使う。別々に決めると、赤の丸がサーモン色に見えるなどのずれが出る。

**順位表示**
- ゴール済みはゴールした順、走っている間は「低い位置にいる順」。
- **「このコマまでにゴールした玉」だけをゴール順に使うこと。** 最終結果の表をそのまま並べ替えに使うと、
  レース中から結果どおりの順で表示されてしまう（実際にこの不具合を出した）。

## 8. 確かめる手順

速いものから順に確かめます。

| 手順 | コマンド | 時間 | 確かめること |
|---|---|---|---|
| ① 物理だけ | `python video/blender_marble.py --seed 5 --out DIR --quality none` | 約 10 秒 | 完走するか、何秒か、詰まらないか |
| ② 飛ばし描き | `... --quality preview --step 12` | 約 30 秒 | 見た目、カメラ、ギミックの形 |
| ③ 通しの試し | `python video/make.py marble --seed 5 --preview` | 約 6 分 | 文字、順位、音、最後の表示 |
| ④ 本番 | `python video/make.py marble --seed 5` | 約 60 分 | 送る前の最終確認 |

**コマ画像を残す**: 文字や音だけ直したいときは、環境変数 `KEEP_BLENDER_FRAMES=1` を付けて本番を作る。
コマ画像（約 2GB）が一時フォルダに残り、同じシードで作り直すと絵を描く工程を飛ばせる。

**書き出し中にやってはいけないこと**: `git stash` や `git checkout` で作業中のファイルを一時的に戻すこと。
書き出しが古いコードを読み込んで、直す前の動画ができる（実際に起きた）。先にコミットしてから `git pull --rebase` する。

## 9. ギミックの足し方

`blender_marble.py` の `mod_○○(z, rng, M)` が 1 つのギミックです。

- 受け取る `z` はその区画の上端の高さ。**下端の高さを返す。**
- どの横位置から落ちてきても受け止められる形にする（前の区画の出口は決まっていない）。
- 部品は `ramp()`（坂）、`peg()`（釘）、`box()`（箱）で作る。動かす物は `kinematic=True` と `drive()`。
- できたら `MODULES` に足し、`build()` の `order` の一覧にも名前を足す。
- §5 の「すき間の目安」と「平らな面を作らない」を守り、§8 の ① を 20 個以上のシードで回す。

いま入っているもの: ジグザグ坂・釘の板・回る羽根・じょうご・階段・振り子ハンマー・水車。
向いていないもの: 宙返りのループ、自由に揺れるシーソーや振り子、ドミノ、細いレール（どれも物理が不安定になりやすい）。

## 10. 新しい 3D の型の足し方

`faces`（布）が、いちばん小さい見本です。

1. `video/blender_○○.py` を作る。`--seed --out --quality` を受け取り、コマ画像と記録（json）を書き出す。
2. `sims_3d.py` に `run_○○(v, rng)` を足す。`_blender()` で 1 を呼び、`_frame()` で絵を読んで文字と音を重ねる。
3. `registry.py` の `SIMS` と `COPY` に足す。`"search": False` と `"heavy": True` を付ける
   （`make.py all` に入らなくなる）。
4. ワークフロー 2 本の「3D の型だけ Blender を入れる」条件に名前を足す。

## 11. 鉄琴の 2 個版（`chime2`）の考え方

1 個版（`chime`）の経路をそのまま使い、2 個のボールが鍵盤を **1 枚おきに** 踏みます。

- 経路は 1 本だけ作る（`sims_course.arc_layout`）。2 個の経路を別々に作ると、離れていってカメラに収まらない。
- 銀は 0・2・4…番目、金は 1・3・5…番目の鍵盤に着地する。着地点と時刻が決まっているので、
  あいだの弧は計算で 1 つに決まる（`two_ball_legs`）。物理は使わない。
- 1 個あたりの間隔が倍になると、同じ重力では弧の高さが 4 倍になって画面から出る。
  2 個版だけ重力を 1.7 分の 1 にしている（`MUSIC_G2`）。高さは 1 個版の約 2.4 倍になる。
- 弧がほかの鍵盤を突き抜けないかを全部調べ、1 か所でも近づきすぎたら経路を作り直す（最大 40 回）。
  ゆっくりした曲（Ode to Joy、Twinkle）はほぼ必ず当たるので、置ける曲が選ばれる。
  速い曲（Turkish March、Für Elise、Mountain King）は、12 回のうち半分以上が当たりなしで置ける。
- 2 個は空中ですれ違うので、奥行きを手前と奥に 0.3 ずつ分けている。

## 12. まだ途中のもの

| もの | 状態 |
|---|---|
| `chime2`（鉄琴の 2 個版） | 低画質の試し書き出しまで確認。本番画質は未確認（約 1 時間かかる） |
| `chime`（鉄琴） | 物理は使わず、先に決めた経路どおりにボールと鍵盤を置いて描くだけなので詰まりがない。鍵盤が小さく見えるので、カメラの近さと鍵盤の大きさは調整の余地がある |
| `faces`（布の比較） | 動くが、布がすぐ滑り落ちて何も映らない時間が長い。球の位置と摩擦の調整が必要 |

| 音 | 合成音を使っている。実際の楽器の録音（著作権のないもの）に替えると心地よくなる見込み |
