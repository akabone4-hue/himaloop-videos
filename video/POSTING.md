# 投稿の準備（YouTube / TikTok / X / Instagram）

2026年11月時点の調査メモです。各社の条件は頻繁に変わるうえ、今回は公式ページを直接開けず検索結果の抜粋で確認した項目があります。「要確認」と書いた項目は、申し込む前に公式ページで確かめてください。

## まず用意するもの

| サービス | 必要な準備 | 動画の条件 |
|---|---|---|
| YouTube ショート | Google アカウントでチャンネルを作る。電話番号認証を済ませる | 縦型または正方形で 3 分以内。1080x1920 推奨 |
| TikTok | 個人アカウント（ビジネスアカウントは報酬プログラムの対象外） | 縦型 9:16 の mp4 |
| X | 通常のアカウントで投稿可 | 無料アカウントは 140 秒・512MB まで |
| Instagram リール | 手動投稿は通常アカウントで可。API を使うならプロアカウント | 縦型 9:16、3 秒〜15 分、300MB まで |

このフォルダで作る動画は 1080x1920・60fps・20〜40 秒の mp4 なので、4 つすべてにそのまま投稿できます。同じファイルを使い回す場合、TikTok のロゴ入りで保存し直した動画を他へ上げると表示が減らされるので、必ず元の mp4 を使ってください。

## 収益化の条件

| サービス | 条件 |
|---|---|
| YouTube | 登録者 1,000 人、かつ「直近 12 か月の視聴 4,000 時間」または「直近 90 日のショート視聴 1,000 万回」。登録者 500 人の下位枠は投げ銭などのみ。2027年2月から新規申請の基準が上がるという報道あり（要確認） |
| TikTok | 報酬プログラムはフォロワー 1 万人、直近 30 日で 10 万回視聴、**1 分以上**のオリジナル動画、18 歳以上。日本は対象国とされる（要確認） |
| X | Premium 加入、認証済みフォロワー 500 人、直近 90 日の表示回数などの条件あり。他サービスと同じ動画の使い回しは対象外とされる（要確認） |
| Instagram | 再生数に応じた支払いは無し。日本で使える収益機能は限定的（要確認） |

TikTok の報酬は 1 分以上の動画だけが対象です。今の動画は 20〜40 秒なので、TikTok で収益化を狙うなら長尺版が別に必要です。

## いちばん大事な注意（YouTube の量産動画ルール）

YouTube は「量産型・テンプレート型で中身が入れ替え可能な動画」を収益化の対象外としています（2025年7月に「不正なコンテンツ」ポリシーとして明確化）。判定はチャンネル単位です。コードで自動生成したシミュレーション動画は、何もしなければこの定義にそのまま当てはまります。

対策として、次を守る前提で運用してください。

- 同じ種類を連続で上げない。種類・配色・ルールを毎回変える
- 「対戦カード」「トーナメント」「シリーズ第◯回」のように、動画ごとに違う見どころを持たせる
- 1 日に大量投稿しない。まずは 1 日 1〜2 本
- 視聴者のコメント（「次は◯◯ vs ◯◯で」など）を次の動画に反映する

抽象的なアニメーションなので、YouTube と TikTok の「AI 生成・合成コンテンツ」の申告ラベルは対象外です（対象は実在の人物や現実に見える映像）。

## 自動投稿（API）の現実

| サービス | 状況 |
|---|---|
| YouTube | Google Cloud でプロジェクトを作り、YouTube Data API と OAuth を設定すれば自動アップロード可能。未審査のプロジェクトからの投稿が「非公開固定」になるかどうかは情報が割れているため、最初の 1 本で確認する |
| TikTok | 投稿 API は審査が必要で、審査前は非公開投稿のみ。自分のアカウント用のアプリは審査に通りにくいという報告あり（要確認）。当面は手動投稿が現実的 |
| X | API は従量課金（1 投稿あたり数円程度、要確認）。自動投稿アカウントは「自動」ラベルの設定が必要 |
| Instagram | プロアカウントと Meta のアプリ設定が必要。1 日の投稿数に上限あり |

おすすめの順番は次のとおりです。

1. YouTube と TikTok に手動で数本ずつ上げ、どの種類が見られるかを確かめる
2. 反応の良い種類に絞って本数を増やす
3. YouTube の自動アップロードを設定する（非公開で上げて、確認してから公開）

## YouTube の自動投稿を有効にする手順

一度だけ、Google 側で認証情報を作って GitHub に登録します。20〜30分ほどかかります。登録が済むと、毎日 7:10 と 23:10（日本時間）の 2 回、1 本ずつ自動で投稿されます。朝はアメリカの夕方、夜は東南アジアと日本・韓国の夜にあたります。

Google の管理画面は表示名や配置がよく変わります。下の名称と違っていたら、近い名前の項目を選んでください。

**A. Google Cloud でプロジェクトと API を用意する**

1. YouTube チャンネルを作ったのと同じ Google アカウントで `console.cloud.google.com` を開く
2. 画面上部のプロジェクト選択から「新しいプロジェクト」を作る（名前は何でもよい）
3. 左メニューの「API とサービス」→「ライブラリ」で「YouTube Data API v3」を検索し、「有効にする」を押す

**B. 同意画面を設定して公開する**

4. 「API とサービス」→「OAuth 同意画面」を開く。ユーザーの種類は「外部」を選び、アプリ名と自分のメールアドレスを入れて保存する
5. 同じ画面の「対象」または「公開ステータス」で「アプリを公開」を押し、「本番環境」にする

手順 5 を飛ばして「テスト」のままにすると、認証が 7 日で切れて毎週やり直しになります。審査の申請は不要です。

**C. クライアント ID を作る**

6. 「API とサービス」→「認証情報」→「認証情報を作成」→「OAuth クライアント ID」を選ぶ
7. アプリケーションの種類は「ウェブ アプリケーション」にする
8. 「承認済みのリダイレクト URI」に次を追加して作成する

```
https://developers.google.com/oauthplayground
```

9. 表示された「クライアント ID」と「クライアント シークレット」を控える

**D. リフレッシュトークンを取得する**

10. `https://developers.google.com/oauthplayground` を開く
11. 右上の歯車を押し、「Use your own OAuth credentials」にチェックを入れて、手順 9 の ID とシークレットを貼る
12. 左の Step 1 の入力欄に次を貼り、「Authorize APIs」を押す

```
https://www.googleapis.com/auth/youtube.upload
```

13. 投稿先のチャンネルのアカウントを選ぶ。「このアプリは Google で確認されていません」と出たら、「詳細」→「（アプリ名）に移動」→「許可」と進む
14. Step 2 の「Exchange authorization code for tokens」を押し、表示された「Refresh token」を控える

**E. GitHub に登録する**

15. GitHub のリポジトリで「Settings」→「Secrets and variables」→「Actions」→「New repository secret」を開く
16. 次の 3 つを 1 つずつ登録する

| Name | 値 |
|---|---|
| `YT_CLIENT_ID` | 手順 9 のクライアント ID |
| `YT_CLIENT_SECRET` | 手順 9 のクライアント シークレット |
| `YT_REFRESH_TOKEN` | 手順 14 のリフレッシュトークン |

この 3 つはパスワードと同じ扱いです。チャットやファイル、メモアプリには貼らず、GitHub の Secrets にだけ入れてください。

**F. 動作確認**

17. 「Actions」タブ →「Post Video」→「Run workflow」を押す。初回は「公開設定」を `private` にして実行する
18. 実行結果ページの上部に投稿先の URL が出る。YouTube Studio で動画とタイトルを確認する
19. 問題なければ、YouTube Studio でその動画を公開にする。以降は毎日自動で公開投稿される

確認のときに、指定した公開設定と違う状態で登録された場合は、実行結果に注意書きが出ます。Google の審査を受けていない API プロジェクトからの投稿は、非公開に固定されることがあるためです。その場合は自動で上がった動画を YouTube Studio で手動公開する運用になります。

## アプリを本番に切り替える手順（認証が 7 日で切れないようにする）

Google のアプリが「Testing」のままだと、リフレッシュトークンが 7 日で失効して自動投稿が止まります。「In production」に切り替えるには、誰でも見られるホームページとプライバシーポリシーの URL が必要です。2 枚のページは `site/` に用意してあるので、無料の GitHub Pages で公開します。

**A. 公開用のリポジトリを作る**

1. `https://github.com/new` を開く
2. 「Repository name」に `uploader-site` と入力する（ページ内のリンクがこの名前を前提にしています）
3. 「Public」を選び、「Add a README file」にチェックを入れて「Create repository」を押す

**B. ページを置く**

4. 作ったリポジトリで「Add file」→「Upload files」を押す
5. `index.html` と `privacy.html` の 2 つをドラッグして入れ、「Commit changes」を押す

**C. GitHub Pages を有効にする**

6. そのリポジトリの「Settings」→ 左メニューの「Pages」を開く
7. 「Branch」で `main` と `/ (root)` を選び、「Save」を押す
8. 1〜2 分待ってから次の 2 つを開き、ページが表示されることを確認する

```
https://akabone4-hue.github.io/uploader-site/
https://akabone4-hue.github.io/uploader-site/privacy.html
```

**D. Google Cloud に URL を登録する**

9. Google Cloud の「OAuth consent screen」→「Branding」を開く
10. 「Application home page」に 1 つ目の URL、「Application privacy policy link」に 2 つ目の URL を入れる
11. 「Authorized domains」の「Add domain」を押し、次を入れて「Save」を押す

```
akabone4-hue.github.io
```

**E. 公開する**

12. 「Audience」を開き、「Publish app」→「Confirm」を押す
13. 「In production」になれば完了。「verification（審査）が必要」という表示が出ても、自分専用で使うぶんには申請不要

**F. リフレッシュトークンを取り直す**

テスト中に発行したトークンは 7 日で切れるので、本番に切り替えたあとで 1 回だけ取り直します。

14. OAuth Playground で「Authorize APIs」→「Exchange authorization code for tokens」をやり直し、新しい「Refresh token」をコピーする
15. GitHub の Secrets で `YT_REFRESH_TOKEN` の鉛筆アイコンを押し、新しい値に入れ替える

## 数字を自動で集める（再生数・平均視聴率）

1 日 1 回、投稿した動画の数字を集めて [`docs/stats/README.md`](../docs/stats/README.md) に表を作ります。動画ごとの再生数・高評価・コメント数・平均視聴率・登録者の増減と、種類ごとの平均が並びます。

最初に登録した権限は「アップロード」だけなので、数字を読む権限を追加します。5 分ほどの作業です。

1. Google Cloud の「APIs & Services」→「Library」で「YouTube Analytics API」を検索し、「Enable」を押す
2. OAuth Playground を開き、歯車の中に Client ID と Client secret が入っていることを確認する
3. 「Step 1」の入力欄に、次の 3 つを 1 行でそのまま貼り、「Authorize APIs」を押す

```
https://www.googleapis.com/auth/youtube.upload https://www.googleapis.com/auth/youtube.readonly https://www.googleapis.com/auth/yt-analytics.readonly
```

4. 警告が出たら「Advanced」→「Go to uploader (unsafe)」→「Continue」と進む。権限の確認画面では、表示された項目すべてにチェックを入れる
5. 「Step 2」の「Exchange authorization code for tokens」を押し、新しい「Refresh token」をコピーする
6. GitHub の Secrets で `YT_REFRESH_TOKEN` を新しい値に入れ替える
7. Actions の「Video Stats」を Run workflow で実行し、`docs/stats/README.md` に数字が出ることを確認する

追加されるのは読み取りの権限だけです。動画の削除や編集はできません。TikTok と X の数字は自動では取れないので、各アプリの画面で確認してください。

## 自動投稿のしくみ

- 投稿する動画は `video/post_queue.txt` の上から順に決まります。1 行が 1 本で、投稿されると行が消えます
- リストが空になると、9 種類を日替わりで回しながら、新しい展開の動画を自動で作って投稿します
- 特定の種類を今すぐ出したいときは、「Post Video」の Run workflow で種類を指定します
- 投稿のたびに [`docs/posts/README.md`](../docs/posts/README.md) が更新されます。動画ファイルのダウンロードリンクと、TikTok・X にそのまま貼れる文面が並ぶので、そこを見るだけで手動投稿できます
- 動画ファイルは Releases の「videos」に置かれ、消えません
- 止めたいときは、Actions タブで「Post Video」を選び、右上の「…」から「Disable workflow」を押します

## タイトル・説明文の決め方

投稿文は `video/registry.py` の `COPY` で種類ごとに定義しています。

- **タイトルは動画ごとに言い回しが変わります。** 同じ題名の連投は検索でも量産判定でも不利なので、種類ごとに 3 通りを用意し、武器名や曲名も入れています
- **結果は書きません。** 「どっちが勝つ？」の答えをタイトルに書くと、最後まで見る理由がなくなります
- **タイトルは英語、日本語版は翻訳として登録します。** 日本語設定の視聴者には日本語のタイトルと説明文が、それ以外には英語が表示されます
- **ハッシュタグは種類を表すものを先頭に置きます。** YouTube は先頭 3 個をタイトルの上に表示します。数は 7 個に抑えています（15 個を超えると全部無視されます）
- **説明文の 2 行目は問いかけです。** コメントが付くと表示されやすくなるので、「何色を選んだ？」のように答えやすい質問にしています

ショートのおすすめ表示は、タイトルよりも「最初の 1〜2 秒でスワイプされなかった割合」と「最後まで見られた割合」で決まります。文面の最適化は検索と分類には効きますが、伸びるかどうかは動画の冒頭でほぼ決まる点は知っておいてください。

## 伸びた実績のある型（調査結果）

| 型 | 状況 | このフォルダでの対応 |
|---|---|---|
| 武器ボールの対戦 | 2025年後半に TikTok と X で流行。現在いちばん勢いがあるが、模倣も多い | `weapon` |
| ブロック掘り・ブロック崩しレース | 武器ボール以前の定番 | `bricks` |
| ボールの脱出・巨大化（曲つき） | 2023年末〜2024年前半に数千万回再生の例。現在は飽和気味で、量産ルールに最も引っかかりやすい | `rings` `grow` `multiply` |
| 陣取り合戦 | 2024年初めに元ネタが数百万回再生 | `colorwar` |
| 国旗マーブルレース | 爆発的ではないが安定。長尺が中心 | `marble`（色のみ。国旗版は未対応） |
| 倍率ゲートつきのマーブル対戦 | 根強い人気。長尺向き | 未対応 |
| トーナメント形式 | 単発より続き物として見られやすく、量産ルール対策にもなる | 未対応（`weapon` と `battle` を流用して作れる） |
| ソートの可視化 | 長尺で数百万〜1,900万回再生の例。ショートでの実績は不明 | 未対応 |

キャラクター、企業ロゴ、配信者の顔、流行りの版権キャラを使う型は権利上の危険があるので作りません。国旗は使えます。

## 時刻どおりに投稿する（外部サービスから呼ぶ）

GitHub の予定実行は、このリポジトリでは 3〜9 時間遅れたり、抜けたりします（2026-11-15〜17 の実測）。
30 分おきに 5 回ぶん予定を入れて確率を上げてありますが、GitHub の中だけでは時刻を保証できません。
時刻どおりに出すには、外部のサービス（cron-job.org など）から、決まった時刻にこのワークフローを呼びます。
呼び出しが先に投稿すれば、遅れて届いた GitHub の予定実行は「今日の分は投稿済み」で何もせず終わります（二重投稿にはなりません）。

cron-job.org での設定（価格通知で使っているものと同じ形です。そのジョブを複製して URL と時刻を変えるのが早い）:

| 項目 | 値 |
|---|---|
| URL | `https://api.github.com/repos/akabone4-hue/himaloop-videos/actions/workflows/post-video.yml/dispatches` |
| 方式 | POST |
| 実行時刻 | 毎日 7:10 と 23:10（タイムゾーン Asia/Tokyo。Custom で Hours に 7 と 23、Minutes に 10。crontab は `10 7,23 * * *`） |
| ヘッダー | `Authorization: Bearer （GitHub のトークン）` ／ `Accept: application/vnd.github+json` ／ `Content-Type: application/json` |
| 本文 | `{"ref":"main"}` |

トークンは GitHub の Settings → Developer settings → Fine-grained tokens で作ります。
対象はこのリポジトリだけ、権限は **Actions: Read and write** だけにします。トークンの値は cron-job.org の画面にだけ入力し、
チャットやファイルには書かないでください。うまくいくと、呼び出しの結果は「204」になります。

投稿時刻や回数を変えるときは、cron-job.org の時刻と、`video/next_post.py` の `POST_TIMES` を合わせます（`.github/workflows/post-video.yml` の cron は予備なので、各時刻の 1 時間後にしておく）。

自動投稿を一時的に止めたいときは、`video/post_config.json` の `hold_until` に日時を入れます（その時刻より前は、呼び出しが来ても何もせず終わります）。
